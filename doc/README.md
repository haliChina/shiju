# doc/ — 名言征集与核查管线

这个文件夹是给 **Agent / 大模型** 用的工作区：按统一流程搜集名人名言，核查真实有效后，
产出符合拾句导入格式的 JSON，用户在网页里「设置 → 数据管理 → 导入」即可把整包句子导入自己的句库。

导入后，带核查信息的句子会在卡片上显示绿色的「已核查」徽章，详情页会展示出处与原文链接。

## 目录

| 路径 | 用途 |
|---|---|
| `AGENT_GUIDE.md` | Agent 操作手册：搜集 → 初筛 → 核查 → 产出 JSON 的完整流程与红线 |
| `SCHEMA.md` | 导入 JSON 的字段规范（含核查溯源字段），与网页导入校验保持一致 |
| `inbox/` | 草稿区：未核查或核查中的句子先放这里，**不要直接导入网页** |
| `quotes/` | 已核查成品包：`verified-XXXX-主题.json`，可直接导入 |
| `tools/validate_quotes.py` | 校验脚本：检查格式、重复、溯源字段是否齐全 |

## 流程一图流

```
搜集候选 → 放进 inbox/draft-*.json → 按 AGENT_GUIDE 核查（原文出处 + 作者归属）
→ 通过校验脚本 → 移入 quotes/verified-*.json → 用户在网页导入
```

## 核心原则

1. **宁缺毋滥**：查不到一手出处（原著原文 / 权威版本）的句子不进成品包，留在 inbox 并注明原因。
2. **原文一字不改**：content 必须是核对过的原文，异文要在 `verifyNote` 里说明取舍。
3. **不伪托**：作者存疑就如实写存疑（如《满江红》归属争议），绝不为了“名气”硬安作者。
4. **溯源可复查**：每条成品必须带 `source`（具体到篇目），填了 `sourceUrl` 的必须是实际打开核对过的页面。
