# Agent 操作手册：搜集与核查名人名言

你（Agent / 模型）的任务：为拾句搜集名人名言，**逐条核查真实有效**后，
产出可直接导入网页的 JSON。字段规范见 `SCHEMA.md`，成品示例见 `quotes/verified-0001-classics.json`。

## 第一步：搜集候选

- 来源优先级：原著数字化文本（维基文库、中国哲学书电子化计划 ctext.org、古诗文网等）
  > 权威出版物 > 百科 / 辞典 > 普通网页。
- 每批聚焦一个主题（如「励志诗句」「论语精选」「鲁迅散文」），一批 10–25 条。
- 候选先写入 `inbox/draft-<主题>-<日期>.json`，字段同成品格式，但 `verified` 填 `false`，
  `verifyNote` 写待核查点。

## 第二步：核查（每条必做）

对每条句子核查三件事：

1. **原文核对**：在原著文本中找到这句话，逐字比对（含标点取舍）。
   - 常见的讹传：断章取义（如「天才就是 1% 的灵感加上 99% 的汗水」后半句被删）、
     异文（如王安石「自缘身在最高层」常被写成「只缘」）、张冠李戴。
2. **作者归属**：确认作者与篇目。归属有学术争议的，在 `verifyNote` 注明「归属有争议，一般归 X 名下」，
   不要隐瞒；完全查不到出处的网络流行句（如多数署名“泰戈尔”“爱因斯坦”的中文格言）直接淘汰。
3. **出处落字**：`source` 写到篇目一级，如 `李白《将进酒》`、`《论语·学而》`、`鲁迅《故乡》`。
   `sourceUrl` 只填你实际打开并核对过的页面链接，没打开过就不填。

核查结果分流：

- 全部通过 → `verified: true`，`verifiedAt` 填核查日期，`verifyNote` 写核查依据（一句话）。
- 淘汰 → 从草稿中删除，或保留在 inbox 并在 `verifyNote` 写明淘汰原因（如「查无此文，系伪托」）。

## 第三步：产出与自检

1. 成品命名：`quotes/verified-<四位序号>-<主题英文>.json`，序号递增不复用。
2. `id` 规范：`vq-<四位全局序号>`（如 `vq-0021`），全仓库唯一，不要复用已发布 id。
3. 运行校验：

   ```bash
   python3 doc/tools/validate_quotes.py doc/quotes/verified-XXXX-主题.json
   ```

   校验不通过不许交付。
4. 交付说明里列出：本批主题、条数、每条的出处、淘汰了哪些及原因。

## 红线

- 不许凭记忆“写”名言再倒推作者——先找到原文，再写进 JSON。
- 不许把搜索引擎摘要、其他名言网站的转引当作核查依据（它们经常互相抄错）。
- 不许改写原文来“通顺化”；原文有生僻异文时保留原文，在 `verifyNote` 说明。
- 一条句子只收录一个版本；异文版本在 `verifyNote` 注明即可，不要重复收录。
